# Парсер C-Level вакансий — «Кадровые резервы.РФ»

Ежедневный сборщик Executive-вакансий по России из публичных страниц:
hh.ru, rabota.ru, career.habr.com, публичная выдача LinkedIn Jobs,
открытые карьерные сайты компаний и публичные Telegram-каналы (через t.me/s/).
Без API job-сайтов и без авторизованной браузерной автоматизации.

## Запуск

```bash
pip install -r requirements.txt
python parser.py
```

Результат:
- `vacancies.json` — структурированный список (title, company, url, salaryText,
  salaryLevel, summary, verified, source…) — готов для загрузки в портал/бота
- `digest.md` — человекочитаемый дайджест
- `seen.json` — память дедупликации между запусками (не удаляйте)

## Логика (соответствует ТЗ)

1. Поиск по списку запросов `SEARCH_QUERIES` (CEO…CCO, все «директора», MD/GM/CM, VP, Head of).
2. Фильтр названий: `TITLE_INCLUDE` / `TITLE_EXCLUDE` (отсекаются ассистенты,
   директора магазинов/ресторанов/филиалов/складов и т.п.).
3. Для каждой новой вакансии открывается первоисточник: проверяются доступность
   и отсутствие маркеров «в архиве», «закрыта», expired. Сохраняется точная HTTPS-ссылка.
4. Зарплата не выдумывается: если работодатель её не указал —
   «Вознаграждение по договорённости», `salaryLevel = 0`.
5. Сортировка: раскрытая зарплата и её верхняя граница (в рублях, USD/EUR
   пересчитываются по `FX_RATES`) → свежесть → масштаб ответственности (`scopeScore`).
6. Резюме — краткое и фактическое, полный текст вакансии не копируется.

## Ежедневный запуск

**Railway (cron):** задеплойте папку как сервис и добавьте Cron Schedule
`0 6 * * *` (09:00 МСК). `seen.json` храните в volume, иначе дедупликация
будет сбрасываться при каждом деплое.

**Linux cron:**
```
0 9 * * * cd /path/to/vacancy_parser && /usr/bin/python3 parser.py >> parser.log 2>&1
```

## Telegram-каналы

Предустановлены проверенные живые каналы: `toplevel_job` (TOP LEVEL JOB,
вакансии для руководителей) и `middle_top_vacancies` (миддл/топ от $2500).
Добавляйте свои в `config.TELEGRAM_CHANNELS` (имя без @). Читается публичное
веб-превью `t.me/s/<канал>` — работает только для открытых каналов.

## LinkedIn: двухступенчатая схема

1. Сначала пробуется публичная гостевая выдача LinkedIn Jobs.
2. Если запрос заблокирован или вернулась пустая страница-заглушка,
   автоматически включается запасной путь: поиск публичных страниц
   вакансий LinkedIn через HTML-выдачу DuckDuckGo (без API-ключей).
   Отключается флагом `LINKEDIN_FALLBACK_ENABLED = False`.

## Важные оговорки

- **hh.ru** периодически показывает капчу при частых запросах с одного IP.
  Держите `PAUSE_BETWEEN_REQUESTS >= 3` и не запускайте чаще раза в день.
  У hh.ru есть открытый официальный API (api.hh.ru) без ключа для поиска —
  если позже решите его разрешить, это надёжнее HTML-парсинга.
- **LinkedIn** жёстко ограничивает автоматические запросы и запрещает скрейпинг
  в своих условиях использования — публичная выдача может отдавать пустой ответ
  или блокировать IP. Считайте этот источник «best effort».
- Вёрстка сайтов меняется: селекторы в `parser.py` имеют запасные варианты,
  но раз в пару месяцев проверяйте, что источники по-прежнему отдают карточки.
- С российского хостинга LinkedIn может быть недоступен; с зарубежного
  (Hetzner и т.п.) — наоборот, стабильнее.
